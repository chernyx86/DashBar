# DashBar — пробная миграция

Один ответственный пользователь на заведение. Его идентификатор назначается
в таблице заведений. Точки внутри этого заведения доступны ему. Роли
«управляющий», «барменеджер» и «старший бармен» обозначают должность этого
пользователя. Пробная схема не требует назначения трёх отдельных ролей.

## Как проверить

Нужна отдельная пустая тестовая база PostgreSQL 15 или новее и роль
администратора тестовой базы. Запустите из каталога архива.

    psql -X -v ON_ERROR_STOP=1 -d barmanager_trial -f 01_schema.sql
    psql -X -v ON_ERROR_STOP=1 -d barmanager_trial -f 02_smoke_test.sql

Тест создаёт два заведения и проверяет область видимости без контекста
и под каждым пользователем. Повтор JSON-импорта возвращает прежний пакет.
Подтверждённый приход сохраняется в буфере для сверки. Неправильный JSON
и загрузка в чужую точку отклоняются. Тестовые данные
и роль удаляются при откате проверочной транзакции.

## Что видно на одном товаре

- Остаток 4 л, расход 14 л за 7 дней, запас на 2 дня при пороге 3 дня.
- Учёт 5 л, факт 4 л, расхождение −1 л. Пустой факт остаётся неизвестным.
- Сопоставимая накладная 120 ₽/л против 100 ₽/л на дату, 10 л, разница 200 ₽.
- Подтверждённая исправленная версия накладной меняет месячный итог на 250 ₽.

## Границы пробы

В буфер импорта записывается раздел data резервной копии «Своего бара» версии 2.
Это исходные записи для проверки человеком. Расчёты используют отдельно
подготовленные подтверждённые данные с известными датами, источниками
и единицами. В пробе расход за период уже рассчитан, а его последний день
совпадает с датой остатка. При неизвестных исходных данных расчёт запаса
пропускается. Месячная сумма включает только положительные отклонения
по сопоставимым строкам. Правило порога и показатель охвата требуют
доработки перед пилотом.

Схема предназначена для проверки модели данных. В пробе нет подключения
HTML, доставки уведомлений, вызова ИИ, маршрута подтверждения буфера или
входа пользователя. Приложение должно будет выставлять контекст только
на сервере после проверки сессии, без прямого доступа клиента к PostgreSQL.
